# 顔の設計と第8版の制作

## 現在の顔の方針（2026年10月4日）

ユーザー指定により、マスピ顔も許容する。マスピ顔であること自体を不採用理由にしない。人物の3特徴と参照画像は一貫性を確認するために使い、場面に合う表情を確認する。以下の線・瞳・輪郭の指定と修正経緯は第8版制作時の記録で、今後の全作品に一律に課す顔の条件ではない。今回の方針変更では、完成済みの画像・生成指示・検品記録は変更しない。

「マスピ顔禁止」の一語ではなく、人物ごとに目・眉・輪郭など髪以外の3特徴を選び、角度・表情を変えても保つ。描画方法は別に指定する。外側の線を太く、内側を少数の細線にし、肌をマットな白、瞳を単純な黒と最大1点の反射にする。背景・服・髪を均一に細密化しない。魅力や表情は残す。

## 汎用設定

```json
{
  "version": 8,
  "cast": {
    "person": {
      "faceDesign": {
        "traits": ["まぶた・目の形", "眉の特徴", "頬・顎・鼻の特徴"],
        "reference": "works/my-story/assets/characters.png",
        "settingBasis": "原作の指定と漫画用の補足を区別して記入"
      }
    }
  },
  "references": ["works/my-story/assets/characters.png"],
  "referenceRoles": {
    "works/my-story/assets/characters.png": "人物の顔の形と描画方法の基準。別の構図参照の顔へ置き換えない。"
  }
}
```

1. 原作とページ設計を確認し、人物ごとの顔の候補を比較する。
2. 採用した顔の正面・斜め・横顔と、作品に必要な表情集を作る。衣装は場面設定で切り替える。
3. referenceRoles で参照する部分を明記する。顔・描画方法・構図・衣装・小道具を混同しない。
4. plan を作り直し、基準画像と現在のネームを画像生成ツールへ渡す。新しい画像を実際に生成する。
5. 顔・口・手・小道具の位置を測り直し、採用、合成プレビュー、ページ確認を行う。
6. quality-plan の縮小・100%・200%を見て8項目を記録する。faceIdentity に各顔の3特徴と、その場面の表情について観察を書く。
7. 不備は画像を修正してから再確認する。素材と参照、確認記録を固定し、パッケージを作る。

第8版では、caption 以外の人物に3特徴・参照・設定の根拠を要求する。品質記録では見えている全顔の faceIdentity、正しい参照、3特徴の観察、表情の観察を要求する。参照のバイト列・役割・顔設定を変えると、生成計画や品質記録は古くなる。これは画像を自動で同定する検査ではなく、未確認を完成扱いにしないための記録の検査である。

## 今回の方針

- 悠真：横長で少し垂れた目、目に近い直線の太眉、幅のあるやわらかい角の顎。
- エリシア：直線寄りの上まぶた、短めの眉、丸い頬と短く丸い顎。髪は原作の赤みを白抜きで表す。
- 王：重いまぶた、広い鼻と厚い頬、四角いひげ。王であること以外の外見は漫画用の補足。

最初の候補は顎の尖りと細い髪線が残ったため不採用。角度・表情集を作り、エリシアの下顎だけを部分修正した。比較画像、採用した表情集、実際の生成指示と参照、採用判断は作品内へ保存する。修正済みの08-2の手は保持し、残り26コマを8ページの素材として描き直す。保持素材を新規生成に数えない。

ページ素材が既存の個別コマよりよくなった場合、`node cli/workflow.mjs use-page 04-2 --reviewed --reason "新ページの顔を確認し採用"` で旧コマを履歴へ移し、ページ素材に戻せる。先に新ページを accept する。履歴画像は削除しない。

## 第8版の実施結果

8ページの素材を生成し、26コマを描き直した。08-2の修正済みの左手と薬指の銀輪は元PNGのまま保持した。04-2・04-3の旧顔素材は履歴へ移し、新ページの顔を採用した。

生成後、02-1の誤った前掛けを礼装へ修正、03-2の樹皮と草を輪郭へ削減、07のエリシアの顎を部分修正した。空吹き出しは画像編集で除去し、文字と尾を別組版で配置した。実際の口・顔・手・小道具を再計測し、特に07-1の悠真のセリフは合成確認で右上へ移して尾を顔に近づけた。

全27コマを25%・100%・200%で確認し、8項目と各顔の観察を記録した。髪で隠れる目・眉や、椅子で隠れる王の顔は、不可視と明記して可視の特徴と前後のコマを照合した。機械検査は記録の完全性・素材変更後の失効・配置の整合性を確認する。

生成時点のネームは `works/kensei/workflow/generation-inputs-v8/`、実際の指示・入力順・参照役割・ハッシュ・採否は `face-generation-v8.json`、部分修正前の画像は `assets/generation-v8/` に保存した。採用素材と組版用の位置情報、確認記録から同じSVG・HTMLを再構築する。

## 根拠と限界

[OpenAIのImage prompting](https://developers.openai.com/api/docs/guides/image-prompting)の具体的な形・画材・構図の指定、入力画像の役割付け、編集で維持する特徴の明示、出力の照合を応用した。[公式のキャラクター参照例](https://developers.openai.com/cookbook/examples/multimodal/image-gen-1.5-prompting_guide)も継続場面での基準画像を扱う。ここで選んだ顔の3特徴は本作品の編集判断で、公式が回避率を検証した処方ではない。

新しいAI生成は非決定的で、一貫性は毎回確認する。自然さ・魅力・AIらしさの完全消失は機械検査で保証しない。再現できるのは採用済み素材からの組版。生成手段は組み込みimage_gen、正確なモデルIDはツールが公開していないため null として記録する。

# 複数作品対応の漫画制作（第5版）

原作・登場人物・絵柄・素材・出力を作品単位で分離しました。最新の使い方と確認手順は [REPRODUCE.md](../../REPRODUCE.md)。既存作品は [works/kensei/output/reader.html](../../works/kensei/output/reader.html)。別作品の雛形は [works/sample/workflow.json](../../works/sample/workflow.json)。

`node new-work.mjs my-story "作品タイトル" "原作本文.txt"` で追加し、PowerShellで `$env:MANGA_PROJECT='works/my-story/workflow.json'` を指定します。

制作順は、原作→脚本・セリフ→ページ構成→人物基準素材→ネーム→画像生成→取り込み→実画像上の座標調整→位置確認→完成出力。画像生成と目視確認はCodexで行い、共通CLIが配置・検査・失効管理・再構築を扱います。

`npm run check` で汎用化と再発防止を検証します。`npm run reproduce` で採用素材から同じSVG/HTMLを再構築します。未確認の位置情報、顔への重なり、尾の交差、曖昧なセリフ順を含む作品は完成出力を止めます。

以下は旧版の記録です。最新コマンドと保存先は上記手順を使ってください。

`output/index.html` をブラウザで開いてください。上から下、台詞は右から左へ読みます。ブラウザ印刷でPDFに保存できます。SVGには絵と台詞が入り、文字は編集可能です。

## 再制作

Node.jsだけで脚本検証・生成指示・組版が動きます。

```sh
npm run check
npm run prompts
npm run build
npm run export
```

1. `story.json` の場面と台詞を編集する。
2. `npm run prompts` で `prompts/page-XX.txt` を更新する。
3. Codexの内蔵画像生成にその指示と `assets/characters.png` を渡す。今回の絵は実際にこの方法で生成。
4. 出力を `assets/page-XX.png` として保存する。既存ページを修正するときは同じ画像と設定画を参照し、変更箇所を限定する。
5. `npm run check` と `npm run build` を実行する。

`npm run export` はインストール済みのChrome/Edgeで完成SVGを1024×1536のPNGに書き出します。他の環境では `MANGA_BROWSER` に実行ファイルを指定します。`story.json` の `artBands` は、生成された絵から取り込む各コマの範囲（正規化した1536pxの縦座標と高さ）です。絵を差し替えたらこの範囲も確認してください。

画像生成はCodex内蔵ツールで実施するため、このNodeスクリプト単体では画像モデルを呼びません。APIキー不要の半自動制作です。画像生成を外部APIで無人実行する機能は含めていません。台詞の変更だけなら4の生成工程は不要です。

## 絵柄と品質のルール

- 白黒、筆圧差のある輪郭、控えめなトーン。光沢、過剰なグラデーション、装飾の増殖を避ける。
- 場所が変わるコマだけ、窓・机・柱など少数の形で場面を示す。会話の寄りでは白い背景を使う。
- 共通設定画で顔・髪・礼装・前掛け・鞘を揃える。花傷のある古い鞘を物語の接点として維持する。
- 台詞と吹き出しはSVGで後組みする。生成画像には文字を含めない。読み上げ用の台詞もHTMLの画像代替テキストに保存する。
- 原作の感情変化に合わせて、引き、手元、表情、抱擁を切り替える。
- 視覚検品では、手指・指輪の左右・衣装・髪形・鞘・人物の位置・台詞による顔隠れを確認する。機械テストは台詞の幅、コマ数、ID、エスケープを検証するもので、絵の正しさを保証するものではない。

「AI臭が完全にない」を保証する技術はありません。今回の対策は、過剰な描き込みや不自然な連続性を減らして、読みやすい漫画の演出に寄せる制作判断です。

## 調査資料（2026-10-03確認）

- [漫画背景を人物が際立つよう仕上げる](https://tips.clip-studio.com/en-us/articles/7164) — 白抜きと線の太さの調整。
- [OpenAI画像生成ドキュメント](https://developers.openai.com/api/docs/guides/image-generation) — 参照画像と編集を利用。反復登場人物の一貫性には限界が残る。
- [Manga Generation via Layout-controllable Diffusion](https://arxiv.org/abs/2412.19303) — レイアウト・脚本への対応・キャラ一貫性が別々の課題であるという研究。

貼り付け資料にあるモデルの版番号・公開日・SNS事例は未確認のものを実装前提にしません。今回は利用可能な内蔵画像生成を使い、参照画像、構造化脚本、別組版、目視検品という工程を採用しました。固定3段のコマ割りは短編で台詞と絵の領域を安定させるための簡略化です。

# 修正用の途中保存と工程レビュー

## 途中の状態を残す

原作、脚本、場面設定、顔・小道具の参照、採否候補、生成・編集指示、採用素材、位置、検品記録、ネーム、プレビュー、PDF、作品内の補助スクリプトを保存する。共通処理のソースとテンプレートも一緒に残す。

通常の制作CLIは実行前と終了時に、変更のあった状態を `.manga-history/states/作品ID/` へ保存する。画像などの実体は `.manga-history/objects/` に内容のハッシュ別で保存し、同じ画像を何度もコピーしない。コマンドが失敗した途中状態も残す。元のファイルへのハードリンクで保存しない。

エディタによる直接編集は、編集前と編集後に以下を実行する。作品内の独自スクリプトは `run` で包む。制作CLIを使わずに行った編集の全操作や、導入前に上書きされていたファイルまで復元できるわけではない。

```powershell
$env:MANGA_PROJECT='works/my-story/workflow.json'
node cli/history.mjs checkpoint '脚本修正前'
node cli/history.mjs run node works/my-story/revise-script.mjs
node cli/history.mjs list
node cli/history.mjs extract 保存状態ID tmp/restored-my-story
node cli/history.mjs bundle releases/my-story-intermediate-history.tar.gz
```

`extract` は新しいフォルダへ取り出す。現在の作品や確定パッケージを上書きしない。全ファイルのハッシュを検査してから取り出す。復元した脚本・画像を現行作品に戻す際は、plan・採用・合成・検品を正式にやり直す。古い確認記録を現在の確認として流用しない。

完成原稿の再現パッケージと、全時点の途中状態の履歴パッケージは別物。途中状態も別PCへ持ち運ぶ場合は `history bundle` のパッケージも保存する。履歴フォルダを削除すると途中状態を失うため、ディスクの清掃対象にしない。

## セリフと視線の流れを先に考える

`workflow plan` は `workflow/reading-flow/` に番号付きのネームと計画JSONを作る。青線がセリフの順番。人物の位置・顔・口・保護領域と併せて確認する。`panel.readingFlow` へ `entry`、`exit`、`focus`、`gazes: [{actor, from:[x,y], to:[x,y]}]` を記録できる。座標はページ全体。

最初のセリフへ上・右から入る→相手の反応へ移る→最後の発話や動作から次のコマへ出る、という流れを検討する。人物を並べる順番、目線、動作、余白と、セリフの順番を一緒に設計する。原作に指定された手や位置関係を読み順の都合で変えない。必要なら吹き出しの高さ、ショット、コマ分割を変える。

自動警告は同じコマ内の読み戻りの候補を示す補助。人物の視線やコマ間のつながり、自然さは目視でレビューする。無言のコマでは動作・顔・余白で導線を検討する。

## サブエージェントによる独立レビュー

履歴を渡さない実プロセス起動、決定記録、変更対象の抽出と作画前のsealは [制作モード](PRODUCTION-MODES.md) を参照。新しい節約方式の局所レビューでは、検証済み対応表の原作抜粋を使い、不足時は全文へ戻す。原作・脚本・最終稿は全文確認を維持する。画像だけの初読へ決定記録や正解の脚本を渡さない。

新規作品のstoryboard・lettering・finalは、[二段階の読順確認](PROMPTS.md)を先に行う。画像だけの観察は変更不可の記録として保存し、その後のprepareで原作・脚本・意図した順番を渡す。

脚本の選定は、まず漫画に残ったセリフ・動作だけを順番に読み、その人物が「なぜ今これを言うか」「何を受けて考えを変えたか」を説明できるか確認する。その後に原作と照合する。原作を先に読んだ場合は、その順序も観察へ明記し、省略された前提を知識で補わないよう改めて漫画だけを読み直す。

隣接する問いと返答に加え、作品全体の「動機→試行錯誤→選択→後の感謝・告白・決断」を追う。重要な感情の回収について、前提となる具体的なコマを観察に記す。前提が地の文で宣言されるだけで、本来必要な試行錯誤が消えていないか検討する。原作の範囲が全て対応表に載ることや、OCRが一致することを、この確認の代わりにしない。

「も」「それも」「今みたいに」などは削除した発言や動作を受けていないか確認する。補うときは原作の前提を戻すか、意味を保つ自然な短縮にする。会話を増やして既存コマへ詰め込む前に、反応・沈黙・ページの区切りを再設計する。破綻する省略、心情を弱める省略、意味が自立した許容可能な短縮を区別し、全ての原文を機械的に復元しない。

原作で話者が明記されていない発話は、前後の地の文、動作主、持ち物、後続の返答から割り当てる。交互に話すという推測や、既存画像の人物配置だけで固定しない。「誰が提案し、誰が気遣い、誰が譲ったか」を往復全体で確認し、明示された話者と漫画化時の解釈をレビューで区別する。同じ人物が理由なく直前の提案を撤回する割り当ては、別の解釈も比較する。

登場人物が失敗して学ぶ場面の不適切な返事は、その後の問い返しや訂正を含めて判断する。作中で意図した失敗を自然な正解へ書き換えて成長の前提を消さない。原作から同じ文字列を採っていても、必要な前提や応答を省いた漫画の会話が成立するとは限らない。

レビュー中に正本が変更された場合は、観察した版と最新の版を分けて保存する。旧版の指摘へ新しい版のページ数やハッシュを付けず、修正後の合格は固定した新しいrequestに対する実読で記録する。

新規作品には `productionReview.required: true` を設定する。主担当が作ったものを、実際に起動したサブエージェントに見せる。Node CLIだけでエージェントを呼んだことにしない。

既存の未完成作品へ導入する場合は `node cli/stage-review.mjs enable`。設定の導入だけで過去の工程が確認済みになるわけではない。完成済みの旧パッケージには遡って新しい確認記録を付けない。

| 工程 | レビュー対象 | 主な確認 |
|---|---|---|
| source | 原作全文 | 本編・後書きの区別、因果、時系列、結末 |
| script | 原作全文＋脚本＋対応表 | 全コマの問いと返答、指示対象、謝罪と応答、冗談の前提、人物の口調、心情の因果。途中の別話者の発話を飛ばして結合していないか |
| storyboard（ページ単位） | ネームと配置 | 読順、顔・視線・動作、セリフから反応と次コマへの接続 |
| artwork（コマ単位） | 実際の画像＋参照 | 同一人物、演技、手、小道具、設定と絵の一致 |
| lettering（ページ単位） | 文字合成PNG | 発話順、話者への尾、重なり、状況説明の見え方 |
| final | 全原稿・読書画面・PDF | 結末と伏線、全体の理解、ページ間の流れ |

```powershell
node cli/stage-review.mjs prepare script all
# 返されたrequestと実ファイルを実際のサブエージェントへ渡す。
# 観察・指摘・実際のtask名を含む回答JSONを作品内へ保存する。
node cli/stage-review.mjs record script all works/my-story/workflow/script-review-response.json
node cli/stage-review.mjs check script all
```

`prepare` は入力のハッシュを固定する。サブエージェントは全文・該当画像を読み、具体的な観察を返す。指摘が未解決なら `changes-requested`。修正後は新しいrequestで再レビューする。CLIは入力が変わった回答、未解決指摘を含むpass、エージェント名のない記録を拒否する。実際の起動・目視を行った証拠として回答とタスク名を残すが、エージェントの判断の正しさを機械的に保証するものではない。

脚本のpassには `dialogueReview: {sourceCompared: true, panels: [{panel: "01-1", observation: "原作のどの問い・返答をどう残したかという具体的な観察"}]}` を全コマ分保存する。無言のコマも動作と会話の接続を記録する。原作を知るレビュアーが削除済みの発話を頭の中で補わず、漫画に残った言葉だけで返答・指示語・冗談が成立するか確認する。復元する発話が増えたらコマ割りへ戻り、同じ話者の発話を機械的に一つへまとめて解決しない。旧脚本レビューは新方針での合格として流用できない。

OCRは承認済み脚本との文字一致を調べる補助で、会話選定の自然さを判定しない。元ページの誤ったセリフをそのまま正解にしない。正常な原稿でもOCRが読めない場合は読み取り不能として保存し、別の認識・実画像確認を挟む。読み取り失敗だけで際限なく画像を再生成せず、実際の文字欠落・誤字を確認してから対象ページを修正する。各候補とOCR原文を保存し、再試行上限は自動制作の画像修正上限に従う。

source・script・該当ページのstoryboardの最新合格記録がなければ画像生成の準備を止める。全コマのartwork・全ページのletteringが合格するまで組版完成を止め、finalが合格するまで自動完了を止める。既存作品はこの設定を明示的に導入し、過去の原稿に検品済み記録を捏造しない。

原作末尾の「お読みいただき、ありがとうございます」などの読者向け挨拶は原作資料に保持し、漫画のセリフには入れない。登場人物が物語内で伝える「ありがとう」は残す。説明を追加する場合も、原作由来と漫画の補足を区別し、長い説明で絵と反応を押し出さない。

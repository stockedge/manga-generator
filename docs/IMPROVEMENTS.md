# 第6版で採用した改善

添付の「AIを使ったマンガ作成の最先端：技術・実務・法務の統合分析」を、現在の制作環境へ反映した記録。実装対象は、コマの制御、場面の連続性、選択と修正の記録、編集可能な出力である。

## 根拠と判断

[MangaFlowの原論文](https://arxiv.org/abs/2605.28173) は、計画・参照素材・レイアウト・コマ生成・合成・文字配置を分け、場面と人物・物体の参照を結ぶ記憶を持たせる構成を説明している。[DiffSenseiの原論文](https://openaccess.thecvf.com/content/CVPR2025/html/Wu_DiffSensei_Bridging_Multi-Modal_LLMs_and_Diffusion_Models_for_Customized_Manga_CVPR_2025_paper.html) は、人物の同一性を保ちながらコマごとの表情・姿勢・動作へ適応する問題を扱っている。

ここから、モデルの固定特徴と場面で変わる衣装・状況を別データとして渡す方針を採った。論文のモデルや評価結果を、この実装でも再現したという意味ではない。添付のサービス価格、サービス終了情報、法務の詳細は実装条件に使っていない。

## 実装したもの

| 改善 | 実際の動作 |
| --- | --- |
| コマだけでの制作 | renderMode: panels なら、各コマのPNGだけでページを合成する。ページ全体のPNGは不要。新規作品の標準設定。 |
| 場面の記憶 | sections に舞台・衣装・小道具を保存し、page.section と panel.section で参照する。panel.state でそのコマだけの違いを上書きできる。 |
| コマごとの失効管理 | コマ方式では、そのコマの指示・配置・セリフ・参照・場面状態をハッシュ化する。隣のコマの場面修正で、関係のない採用コマを失効させない。 |
| 候補の比較 | candidate-panel で複数候補を保存し、同じコマの比較HTMLを作る。古い計画の候補を現在の採用素材として取り込むことは拒否する。 |
| 選択・差し替え履歴 | 採用理由、申告された生成手段・モデル名、採用時の指示・参照ハッシュ・由来を記録する。差し替え前後の素材と記録を history に保存する。 |
| 編集用の分離 | layers で、絵と文字・吹き出し・枠を別のSVGへ出力する。両者は同じページ座標で、キャンバス背景は透明。 |
| 確認の維持 | 新方式でも顔・尾・読順の検査と、合成原稿を見た位置確認を必須にする。無言コマの口座標・保護範囲も検査する。 |

候補登録時の指示は登録時点の計画、acceptedJob は採用時点の計画を表す。既存画像の再採用時に、その新しい指示で画像を生成したと解釈しない。生成手段とモデル名は申告値で、不明なら unspecified / null を保存する。由来記録は権利の法的判定や著作物性の証明ではない。

## 既存作品への適用

works/kensei を第6版へ更新。修理店・回想・王宮・結婚後の工房を区別し、01-3ではまだ鞘を身に着けないこと、03-2では回想の衣装、07-4では工房の衣装へ切り替わることを記録した。原作で示された設定と、既存漫画の外見・年齢の補足設定も区別した。

既存作品は renderMode: page で採用済み素材を維持した。8ページを目視確認し、確認用SVGが変更前と一致することを検証した。画像は再生成していない。第6版の目的は、制作と修正の制御を改善することで、既存の絵や物語の面白さが増したと主張するものではない。

## 検証

verify-general.mjs は作品画像に依存しない白いPNGを使い、別の人物・場面設定で次を試す。

- ページ素材なしで、二つのコマ素材から完成出力できる。
- 一つのコマの修正で、もう一つのコマの指示ハッシュが変わらない。
- 回想と現在の衣装が混ざらず、衣装変更で関係するコマが失効する。
- 古い候補、未確認素材、話者不明、顔や尾の交差、曖昧な読順を拒否する。
- 採用理由と履歴が残り、絵のSVGに文字、文字のSVGに絵が混入しない。

既存作品では再構築・読書画面の検証を行い、確定時に freeze と bundle で保存・持ち運びを確認する。

LoRA、ControlNet、研究モデルの導入、外部APIでの無人生成、画像認識による採点、動画・音声化は今回の実装に含めない。現在の画像生成ツールと参照素材で制作できる構成を保つ。

# 読順・場面転換・時間と感情のネーム設計

2026年10月6日のユーザー指摘と資料を反映する。番号が順に並ぶことと、読者が自然にその順を読むことを区別する。近い吹き出しは一組と捉えられるため、同じ人物の1番と3番を近づけ、離れた2番の返答を挟む配置を避ける。

受領資料の原文は [保存済み資料](../research/user-name-design-20261008.txt)、一次資料の確認範囲・採用と留保は [調査記録](./_research-flow-review-20261006.json) に保存する。共通実装の監査結果は [実装監査](./_research-integration-audit-20261008.json) に保存する。

## 資料から取り入れる設計と確認

| 資料の観点 | 制作時の具体的な作業 | 検品で見ること |
| --- | --- | --- |
| 視線・時間・理解順・感情を設計する | ページの purpose / expectation とコマの role / information / pause を決める | 読者が原因や質問の対象を補わずに分かるか |
| 魅せゴマと支えるビート | 必要なページだけ showcase を選び、前後の反応・面積・距離を設計する | 同じ面積とショットの反復で感情の強弱が失われていないか |
| 一コマを一ビートにする | action に中心となる瞬間を記録し、受け渡し・収納・返答を必要に応じて分ける | 同時に描けない前後動作が混ざっていないか |
| 吹き出しと顔を一緒に考える | 会話をまとまりに分け、話者位置と文字領域をラフ段階で決める | 近い後続発話へ飛び、途中の返答を読み落とさないか |
| 場面転換と時間の長さ | transition に入口・出口の手段と原作指定／補足を記録する | 全隣接コマを通して場所・時刻・回想・持ち物の変化が分かるか |
| 寄り・引き・無言の使い分け | camera / pause を感情や必要情報に合わせて決める | 絵と文章が同じ説明を重ねすぎず、反応や余韻を読めるか |
| ページ末から次ページへ | expectation と次ページの情報を合わせる | 問いの答えや行動結果を飛ばさず、続きを知りたい理由があるか |

これらは作者・レビュー担当が記入して判断する設計項目である。項目が埋まったことだけで面白さや理解しやすさを合格にしない。サブエージェントは実際のコマを指して不足を記録し、直した箇所を新しい入力で再確認する。

## 制作の順序

1. 原作全文から、場面ごとの場所・時刻・目的・行動・心情と情報公開順を整理する。読者向け御礼を本編へ入れない。
2. ページで動かしたい感情、重要な瞬間、支えるビート、次に知りたいことを決める。全ページを同じ2コマ・同じサイズへ機械的に割り当てない。コマの面積・寄り方・余白に強弱を付け、無言の反応や余韻も選ぶ。
3. 同時に成立しない複数の動作を1コマに押し込まない。「渡す→受け取る→しまう」の前後が消える場合は動作コマを加える。中心は1ビートとし、表情や小道具で支える。
4. 会話を意味・息継ぎの単位へ分け、発話順・まとまり・改行を先に設計する。文字数だけで切らない。吹き出し→顔や反応→返答へ移れる人物配置を選ぶ。合わなければコマ分割や構図まで戻る。
5. `node workflow.mjs plan` の `workflow/narrative-plan.json` と `workflow/reading-flow/` を確認する。場面・ページ境界、人物左右の逆転、面積とカメラ、近接する非連続発話を検討する。警告は検討候補で、自然さの自動判定ではない。
6. サブエージェントはまず番号・誘導線のないネーム／合成画像を通常の読者のように読み、自然に次に読むセリフを記録する。その後、意図した配列と番号ネームを照合する。脚本を既に知るレビューなので、盲検の眼球運動実験と呼ばない。
7. 参照とネームで作画する。実画像の顔・口・手・小道具を測り直す。尾が正しい人物へ向くだけでなく、その人物の反応を会話の途中で読めるかを見る。
8. 文字合成を番号なしで再読する。前のまとまりを読み終える前に、同じ側の次の発話へ吸い寄せられないか確認する。無理な右→左→右往復は段を明確に分けるか別コマへ分割する。
9. 最終レビューでは隣接ページも通して読む。場面・時間の切れ目、回想の入りと戻り、準備→緊張→解放、ページ末の問いと次ページの答え、伏線と結末を確認する。毎回クリフハンガーや大ゴマを強制しない。
10. 未解決なら `changes-requested`。修正後に新requestで再レビューする。旧passを新配置の承認へ流用しない。素材・指示・失敗・観察を保存し、正式採用・確認・PDF・freeze・bundleへ進む。

コマを分割したときは、複製した `panel.state` も見直す。前コマの「椅子を引いている」「紙を渡している」などを、次コマの静止した返答へ残さない。`scene`・`action`・`transition` と、sectionを合成した現在の物・姿勢が同じ瞬間を指すことを脚本レビューで確認する。分割後は原作対応表のコマIDも更新する。

セリフの話者を変更して絵を保持するときは、実画像の口と演技も確認する。灰色の顔枠では読めても、可視人物が大きく口を開け、その隣に別人の尾なし画面外発話があると、実際の話者を取り違えることがある。配置や配列だけで合格にせず、番号なし合成で確認する。曖昧さが残れば話す本人を映す構図へ戻すか、画面外の声の入口を明瞭にする。可視人物の口を閉じるだけで解決したと扱わない。旧素材を使う理由にも、新しい話者と演技が合う具体的根拠を残す。

sectionの説明に後の動作も含まれる場合は、そのコマでまだ行っていない支持・収納・摘出などを、現在の状態として区別する。生成された絵に次の動作が前倒しされていないか、画像レビューで確認する。連続する寄りでも人物左右や身体の側を無断で反転させない。必要な逆角度は同じ場所を示す引きで導入し、画面の左右と解剖学的な左右を別々に検討する。指示に「右」と書いたことだけで実絵の右側を確認済みにしない。茶器・受皿・未綴じの記録紙など、場面をつなぐ小道具の形と数も直前の採用画像と照合する。

制作中の作品では、実際の独立ネームレビューで「宣言→承諾→依頼」と先読みされる配置を発見し、宣言と「依頼→承諾」を別コマへ分けた。また実画像の吹き出しが茶器を隠す配置は、保護範囲を残したまま意味単位の列と高さを変更して修正した。これらは制作途中の改善例で、全作品の改訂完了や面白さの保証を意味しない。

尾が手や小道具の輪郭へほぼ接して線がつながって見える場合、`dialogue.tailLength`（24〜160の整数、ページ座標での最大長）で短くできる。口のanchorや顔を実際と違う位置へ移さず、尾は引き続き口の方向へ向ける。既定は160。短縮しても話者・顔・保護範囲の交差検査は維持し、実合成で白い隙間と話者の分かりやすさを再確認する。寸法指定だけでは目視合格にならない。

## 場面転換

場所・時刻の変化は、引きの導入、簡素な外観や窓、時計、小道具、短い時刻のキャプションなど、場面に合う手段で伝える。同じ場所の会話では毎コマ背景を描き込まない。伝えた場所の少数の線や持ち物を維持する。

回想は質問・記録・物体などを入口、現在の相手の反応などを出口にする。人物左右の逆角度は自動的に誤りではないが、服・机・持つ物・視線から同じ空間と理解できるか確認する。段・コマ間の余白・無言コマは時間や物語の切れ目を表す選択肢。余白だけで場所や原因が伝わったと扱わず、キャプションで絵の内容を全部言い直さない。

任意の計画情報を作品設定へ保存する。

```json
{
  "transition": {
    "kind": "time-change",
    "bridge": "別れた後、翌日の時計と同じノートを示す",
    "settingBasis": "翌日は原作指定。時計を見せる構図は漫画補足"
  },
  "information": "このコマで読者が初めて知る事実",
  "pause": "返答前の表情を読ませる",
  "readingFlow": {"entry": [950, 50], "exit": [130, 650]}
}
```

`page.showcase` は任意の魅せゴマID。原作指定と補足を区別する。計画だけで、実際に絵へ導入や反応を描いた証拠にはしない。

`workflow plan` の `narrative-plan.json` には、資料の設計を再利用できる形で保存する。ページごとの `intent`（感情、情報公開順、ピーク、ページ末の問いと次ページの答え）、コマごとの面積比・`strength`・`readingGroups`、隣接コマの `ledger`（時刻・場所、読者が知るべきこと、導入アンカー、軸のリセット、保持／変更した小道具、原作指定と漫画補足）を確認する。`showcaseExists:false`、`strengthsEqual:true`、`layoutBoundary:false` は自動不合格ではなく、作者とレビュー担当が強弱・段境界・ページめくりを再検討するための警告である。

台詞群を明示する場合は `panel.readingFlow.groups` を使う。各要素は `{id,row,dialogueIds,order,kind,entry,exit}` とし、`dialogueIds` はそのコマの発話番号（1始まり）を一度ずつ含める。段を変える箇所と話題・場面の境界を合わせる候補として使うが、番号線や配列だけで自然な読順を保証しない。実画像を番号なしで読み、先読み・飛ばし・視線の戻りを記録する。

## 正式レビュー

ページ末と次ページの接続は、`expectation` が埋まっているだけで合格にしない。最終レビューでは実際の最後の発話・視線・動作を入口の手掛かりとして挙げ、次ページのどの絵や発話が応えるかを記録する。静かな余韻や連続する会話は、その意図を説明し、毎回の引きを強制しない。ページめくりで初めて見せたい情報がある作品は、完成した読書画面とPDFの実際の表示単位も確認する。一ページ表示と見開き表示で先に見える情報は異なるため、コマ番号や設定上のページ境界だけで伏せられたと扱わない。現行の機械検査は、見開きの左右・表裏の順序や情報の先見えを自動判定しない。

`plan` が作る `workflow/storyboards-unnumbered/page-01.svg` はコマの番号・ビート解説・読順の誘導線を表示しない検討用ネーム。顔の仮矩形と口の話者IDは残るため、完成した演技を見た記録とは区別する。まずこのネームを読み、次に `workflow/reading-flow/page-01.svg` と照合する。実画像の文字合成では `workflow/review/page-01.png` を先に読む。

```powershell
$env:MANGA_PROJECT='works/my-story/workflow.json'
node workflow.mjs plan
node export.mjs works/my-story/workflow/storyboards-unnumbered
node export.mjs works/my-story/workflow/reading-flow
# 原作と脚本の正式レビューを済ませてから、ネームのrequestを作る
node stage-review.mjs prepare storyboard 01
# 実際のサブエージェントが画像を読み、回答JSONを保存する
node stage-review.mjs record storyboard 01 works/my-story/workflow/storyboard-01-response.json
node stage-review.mjs check storyboard 01
```

storyboard・lettering・finalのpassには以下も必要。対象の全コマを列挙し、無言コマは `dialogue: []`。予測順が意図と違うならpassではなく修正要求。機械検査は記録形式と一致を検査し、実見や自然さを保証しない。

`prepare` の `requiredTransitions` に列挙された実在の隣接コマ境界を、連続場面も含めて各1回記録する。ページ単位のレビューには、そのページ内部と前後ページへの境界が含まれる。架空の境界、重複、未記録は拒否する。作品が1コマだけなど境界がない場合は `transitions: []` を使う。

番号なしネームは `workflow/storyboards-unnumbered/page-XX.svg`。まずこれを読み、次に番号付きネームを照合する。ページ単位requestには前後の場面設定とネームも入り、確認入力の変更で旧レビューは失効する。文字合成レビューでは隣接ページの実画像が存在すれば入力へ含め、まだない場合も欠落状態を記録する。未生成の隣接画像を見たとは扱わず、ネームでの接続確認に限る旨を観察へ残す。後から画像が作られれば、その境界を再レビューする必要がある。

脚本レビュー入力には転換の `bridge`・`settingBasis`、情報公開・間・魅せゴマも含める。台帳の前後設定はsectionとpanel.stateを合成し、同じsection内の場所・時刻・物の状態変化も確認候補として示す。候補警告は不合格の自動判定ではない。

```json
{
  "readingReview": {
    "withoutGuides": true,
    "predictedOrder": [{"panel": "01-1", "dialogue": [1, 2]}],
    "observations": ["実際に次に読んだ発話", "近接・余白・顔との接続の具体的観察"],
    "transitions": [{"from": "01-1", "to": "01-2", "observation": "直前直後の動作・場所・時間がつながる実際の根拠"}]
  }
}
```

自動配置 `layout` も非連続の近い縦クラスタを避ける。解けないならセリフを削って隠さず構図やコマ分割を直す。近接警告の距離係数は実装の経験則で、研究で実証された万能閾値ではない。

文節や息継ぎで縦書きの列を分ける場合は、セリフへ `textColumns` を指定する。例：`"text":"違う。これは、傷じゃない。","textColumns":["違う。これは、","傷じゃない。"]`。空でない文字列の配列を右から左へ配置し、連結が改行を除いた `text` と完全一致することを検査する。指定列は容量で切り直さず、吹き出し寸法と描画が同じ列を使う。語境界を自動推測する機能ではない。変更後は再計画・必要な再採用・合成の実読・工程レビューを行い、長い列が顔や動作を押し潰す場合は構図やコマ分割へ戻る。

## 調査根拠と採用範囲

- [小学館まんが家養成講座](https://www.clipstudio.net/oekaki/archives/152081)：右→左、話者近くへの配置、交差する配置の改善、文節での改行と長文分割。
- [MediBang漫画講座](https://medibangpaint.com/use/2021/06/7-tips-for-drawing-easy-to-read-manga/)：意図しない先読みを生む配置の例。
- [CLIP STUDIO制作ガイド](https://www.clipstudio.net/en/comics-manga/comic-creation/)：ネーム・文字スペースと、場所や時間を示す導入。英語語数を日本語の固定上限へ移さない。
- [Tanaka & Iba, 2024](https://web.sfc.keio.ac.jp/~iba/papers/PLoP2024_MangaPatterns.pdf)：魅せゴマへの構築、吹き出しでの導線、全体からネームへの反復。140件を選定し、そのうち58書籍から133知見を抽出した段階の研究。全作品に同じ演出を強制する規格ではない。
- [Caoら, SIGGRAPH 2014](https://www.ying-cao.com/projects/manga_composition/manga_composition.htm)：人物と吹き出しの統合配置。本システムがその確率モデルや眼球運動計測を実装したとは言わない。
- [Cohnら, 2025](https://pubmed.ncbi.nlm.nih.gov/40179483/)：日本漫画の右→左・下方向の経路と縦列の傾向。固定S字を全ページに当てはめない。
- [Foulsham & Cohn, 2026](https://pubmed.ncbi.nlm.nih.gov/42691285/)：コマの改行と物語境界の関係。吹き出しの具体距離や本システムの読順を実証した研究ではない。

ユーザー資料の例示・数値と研究の内容を区別する。特定秒数の認知負荷、最大コマの必須化、AIらしさの消失、面白さや自然な読順の保証は採用しない。
